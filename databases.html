CATEGORY THREE • DATABASES

Travlr
Database

A full-stack travel application enhanced with backend search and filtering using Angular, Express, Mongoose, and MongoDB.

01 ARTIFACT

The original artifact.

I selected my Travlr application for the Databases category of my CS 499 ePortfolio. The application was originally developed as a full-stack travel application using Angular for the frontend, Express for the backend API, Mongoose for database interaction, and MongoDB for persistent data storage.

The application allows users to view available trips through the Angular interface. When the trip listing component is initialized, it uses the TripDataService to send a request to the Express API. The API retrieves trip records from MongoDB and returns the results to the Angular application.

The backend also supports CRUD functionality for trip information. Users can retrieve an individual trip by its code, add new trips, and update existing trips. The trips controller uses Mongoose to perform these database operations.

The Travlr Mongoose schema defines fields including the trip code, name, length, start date, resort, price per person, image, and description. These fields determine the structure of the trip documents stored in MongoDB.

The original application provided a functional connection between the frontend, backend API, and database. However, the original trip listing retrieved all trip records without allowing users to search or filter the database results.

02 ENHANCEMENT

What I changed.

For my CS 499 capstone enhancement, I added advanced search and filtering functionality to the Travlr application. The enhancement allows users to narrow available trips based on information such as destination, price, and trip length.

The original backend used an empty Mongoose find() query to retrieve every trip from MongoDB. I modified the application so that the user's search criteria can be sent from the Angular frontend to the Express API.

The backend processes those criteria and constructs a Mongoose query based on the values provided by the user. Destination information can be used to narrow the results, while minimum and maximum price values can be used to create a price range. Trip length can also be used as a filtering condition.

The filtering process now takes place on the backend. The user selects search criteria, Angular sends the request to the API, Express processes the request, Mongoose creates the database query, and MongoDB returns only the matching trips. The results are then returned to Angular and displayed to the user.

I also improved the database implementation by addressing data types used for searchable values, validating search parameters, improving error handling, and testing the filtering functionality. These changes make the database functionality more flexible and useful as the number of available trips increases.

03 CODE REVIEW

What I identified.

My code review focused on the structure, efficiency, functionality, error handling, data organization, and maintainability of the existing database implementation.

One of the main limitations I identified was the original tripsList function. It used find({}), which retrieved every trip document from MongoDB regardless of what information the user needed. While this worked with a small dataset, it was not an efficient approach for a larger collection.

I also identified that fields such as length and perPerson were originally stored as strings. Because these values are used for numerical comparisons during filtering, their data types needed to be considered when designing the enhanced database queries.

Another area for improvement was error handling. The original database operations primarily checked whether a query returned a result rather than consistently handling database exceptions. The enhanced implementation provides more appropriate handling for potential errors during database operations.

I also reviewed the existing comments and documentation and improved them where necessary so that they accurately describe the application's updated functionality.

06 NARRATIVE

Project reflection.

This project gave me the opportunity to evaluate an existing full-stack application from a database perspective rather than simply treating the database as a place to store information.

Reviewing the original Travlr code helped me understand how information moves through the application. Angular requests data through a service, the Express API receives the request, the trips controller uses Mongoose to communicate with MongoDB, and the results are returned to the frontend.

The original application retrieved all trips using an unfiltered database query. Identifying this limitation helped me understand how database design and query construction can directly affect the application's functionality and efficiency.

Implementing the enhancement required me to connect frontend user input with backend database logic. I had to consider how search criteria should be transmitted through the API, how Mongoose should construct the query, and how MongoDB should return the appropriate results.

This enhancement demonstrates my growth in database management, full-stack development, API design, problem solving, and code review. It also demonstrates my ability to take an existing application, identify a specific weakness, and implement a meaningful improvement without changing the application's original purpose.
